Networking Basics Every Developer Should Know

2025-02-05
networkingprogramming

You don’t need to be a network engineer, but understanding the basics of how data moves across the internet will make you a better developer.

TCP: Reliable Delivery#

When you make an HTTP request, it happens over TCP. TCP guarantees:

  • Ordered delivery — packets arrive in order
  • No loss — lost packets are retransmitted
  • No duplication — each piece of data arrives exactly once

This is why HTTP works — it can assume a reliable stream underneath.

DNS: Name to IP#

When you type example.com, your OS asks a DNS resolver: “What IP address is this?” The answer gets cached, which is why DNS changes take time to propagate.

example.com → 93.184.216.34

TLS: Encryption#

The s in https means TLS (successor to SSL). The handshake:

  1. Client says “I want to talk securely, here are my capabilities”
  2. Server says “Here’s my certificate and my capabilities”
  3. Client verifies the certificate against trusted CAs
  4. Both derive a shared secret
  5. All further communication is encrypted

This happens in milliseconds, on every HTTPS connection.

HTTP: The Application Layer#

HTTP is built on top of TCP. A request is just text:

GET /index.html HTTP/1.1
Host: example.com

And a response:

HTTP/1.1 200 OK
Content-Type: text/html

<html>...</html>

Understanding these layers helps when debugging: is it a DNS issue? TLS certificate problem? TCP connection refused? Each layer has different symptoms and different fixes.
