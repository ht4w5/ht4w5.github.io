Docker Best Practices for Production

2025-04-02
devopsdockertools

After running Docker containers in production for a few years, I’ve collected a set of practices that have saved me from late-night incidents.

Multi-Stage Builds#

Keep your final image small by separating the build stage from the runtime stage:

# Build stage
FROM node:20-alpine AS builder
WORKDIR /app
COPY package*.json ./
RUN npm ci --production=false
COPY . .
RUN npm run build

# Runtime stage
FROM node:20-alpine
WORKDIR /app
COPY --from=builder /app/dist ./dist
COPY --from=builder /app/node_modules ./node_modules
EXPOSE 3000
CMD ["node", "dist/index.js"]

Don’t Run as Root#

Always create a non-root user:

RUN addgroup -S app && adduser -S app -G app
USER app

Use .dockerignore#

A good .dockerignore prevents leaking secrets and unnecessary files:

node_modules
.git
.env
*.md
dist

Health Checks#

Docker can’t know if your app is actually healthy unless you tell it:

HEALTHCHECK --interval=30s --timeout=3s \
  CMD wget -qO- http://localhost:3000/health || exit 1

These small details compound into reliability over time.
