How to Read Unfamiliar Code

2025-03-15
programmingcareer

Reading code is a skill that’s rarely taught explicitly. You’re expected to just figure it out. Here’s the approach I’ve developed over years of joining new teams.

Step 1: Find the Entry Point#

Every program starts somewhere. For a web app, that’s usually the main server file or the router configuration. For a CLI, it’s main() or the argument parser. Start there and trace the flow.

Step 2: Follow the Data#

Don’t try to understand every function. Instead, follow a piece of data through the system:

  • Where does it come in? (HTTP request, file, database)
  • How is it transformed?
  • Where does it go out?

This gives you a thread to pull on, rather than staring at a wall of files.

Step 3: Read the Tests#

Tests are often the best documentation. They show you:

  • What the code is supposed to do
  • Edge cases the authors thought about
  • How the API is meant to be used
find . -name "*test*" -o -name "*spec*" | head -20

Step 4: Look at Recent Commits#

git log --oneline -20 shows you what’s been changing recently. Active areas of the codebase are where you’ll spend the most time, so start there.

Step 5: Draw a Map#

Literally. On paper or in a text file, sketch out the major components and how they connect. The act of drawing forces you to articulate your understanding, which reveals gaps.

The goal isn’t to understand everything — it’s to understand enough to make your first contribution safely.
