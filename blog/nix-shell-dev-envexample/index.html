Nix Shell for Per-Project Dev Environments

2025-07-22
nixdevopstools

Docker solves the “works on my machine” problem, but it’s heavyweight for dev environments. Nix shells offer a lighter alternative.

A Basic flake.nix#

{
  description = "My project dev environment";

  inputs = {
    nixpkgs.url = "github:NixOS/nixpkgs/nixos-24.05";
    flake-utils.url = "github:numtide/flake-utils";
  };

  outputs = { self, nixpkgs, flake-utils }:
    flake-utils.lib.eachDefaultSystem (system:
      let
        pkgs = nixpkgs.legacyPackages.${system};
      in {
        devShells.default = pkgs.mkShell {
          buildInputs = [
            pkgs.nodejs_20
            pkgs.pnpm
            pkgs.typescript
          ];
        };
      });
}

Entering the Shell#

nix develop

That’s it. You now have Node.js 20, pnpm, and TypeScript available — pinned to exact versions from your lockfile.

Why Not Docker?#

  • Nix shells share your host filesystem natively — no volume mounts
  • Startup is instant vs. container build times
  • You can use your normal editor, debugger, and tools
  • Dependencies are deduplicated across projects

Direnv Integration#

Add a .envrc to auto-enter the shell:

use flake

Now just cd into the project directory and everything is ready.

Nix has a steep learning curve, but the payoff in reproducibility is worth it for teams.
