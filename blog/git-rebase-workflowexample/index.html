A Clean Git Rebase Workflow

2025-02-18
gittools

I used to fear git rebase. Then I learned interactive rebase, and now I can’t imagine working without it.

Why Rebase?#

Merge commits like “fix typo”, “wip”, “actually fix it this time” pollute your history. Interactive rebase lets you clean these up before merging.

The Basic Workflow#

# Rebase the last 5 commits
git rebase -i HEAD~5

This opens your editor with something like:

pick abc1234 feat: add user auth
pick def5678 wip: halfway through tests
pick ghi9012 fix: typo in auth module
pick jkl3456 feat: add password reset
pick mno7890 fix: forgot to add env var

You can then:

  • pick — keep as-is
  • squash — meld into previous commit
  • fixup — like squash but discard this commit’s message
  • reword — keep changes but edit the message
  • drop — remove entirely

After Squashing#

pick abc1234 feat: add user auth
squash ghi9012 fix: typo in auth module
pick jkl3456 feat: add password reset
fixup mno7890 fix: forgot to add env var
drop def5678 wip: halfway through tests

Now your history tells a clean story: two features, each self-contained.

Golden Rule#

Never rebase commits that have been pushed to a shared branch. Rewriting published history causes conflicts for everyone else.

Interactive rebase is one of those tools that takes 10 minutes to learn and saves hours of confusion later.
