SQL Joins Visualized

2025-08-10
databasesqlprogramming

Joins are the bread and butter of relational databases, but they confuse beginners. Let’s fix that.

Sample Tables#

users

idname
1Alice
2Bob
3Charlie

orders

iduser_idproduct
11Laptop
21Mouse
32Keyboard

INNER JOIN#

Returns only rows with matches in both tables:

SELECT users.name, orders.product
FROM users
INNER JOIN orders ON users.id = orders.user_id;

Result: Alice (Laptop, Mouse), Bob (Keyboard). Charlie is excluded — he has no orders.

LEFT JOIN#

Returns all rows from the left table, even without matches:

SELECT users.name, orders.product
FROM users
LEFT JOIN orders ON users.id = orders.user_id;

Result: Alice (Laptop, Mouse), Bob (Keyboard), Charlie (NULL).

When to Use Which#

  • INNER JOIN: You only want records that exist in both tables
  • LEFT JOIN: You want all records from the primary table, with optional related data
  • FULL OUTER JOIN: You want everything from both tables (rare in practice)

Most queries use INNER or LEFT. If you’re writing a RIGHT JOIN, consider swapping the table order instead — it’s easier to read.

The mental model: joins are just Venn diagrams in SQL.
