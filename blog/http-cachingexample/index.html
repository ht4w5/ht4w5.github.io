HTTP Caching Explained

2025-06-05
webnetworkingperformance

Caching is one of the most effective ways to speed up web applications, yet it’s often misunderstood. Let’s demystify it.

Cache-Control Headers#

The Cache-Control header tells browsers (and CDNs) how to cache responses:

Cache-Control: public, max-age=31536000, immutable
  • public — can be cached by CDNs and browsers
  • max-age — how long (in seconds) to consider fresh
  • immutable — the file will never change at this URL

ETags for Validation#

ETags let browsers check if a cached response is still valid:

ETag: "abc123"

On subsequent requests, the browser sends If-None-Match: "abc123". If the resource hasn’t changed, the server returns 304 Not Modified — saving bandwidth.

Strategy by Asset Type#

AssetStrategy
Hashed JS/CSS (app.a1b2c3.js)Cache-Control: public, max-age=31536000, immutable
HTML pagesCache-Control: no-cache (validate every time)
API responsesCache-Control: private, max-age=0, must-revalidate
ImagesCache-Control: public, max-age=86400

The Key Insight#

Cache aggressively with hashed filenames. When the content changes, the hash changes, creating a new URL. Old caches simply expire naturally.

Understanding caching transforms how you think about deployment and performance.
